- [ ] **Incremental re-annotation: re-annotate an already-annotated file with only the new/changed annotators, instead of re-running the whole pipeline** (Mario, 2026-10-01; not yet designed)
  - Motivation: the pipeline is under active iteration (bug fixes, new predictors/annotators — see Phase 2 candidates). Today any change forces a full re-run of a file that is otherwise almost entirely annotated, which for WGS-scale inputs costs days of SpliceAI/Pangolin inference.
  - **Open design questions (to resolve before implementing):**
    1. **Validity of existing annotations** — how to prove a previous output is reusable: same tool/model/database versions as the current config, same parameters (e.g. SpliceAI `-D`, VEP cache/`--pick` flags, consequence/AF filters), same reference FASTA/assembly. Natural source: the per-run manifest (`write_run_manifest.py`, Nextflow entry point only; `main.sh` has none — see Priority 0 provenance item, which this depends on). Annotations from a run with no manifest = unknown provenance → not reusable without explicit override.
    2. **Region/variant coverage** — confirm the prior run covered the same regions (gene restriction BED, chunking, filters that dropped variants) and the same variant set as the new input; define what happens to variants present now but absent before (annotate fully) or the reverse (drop/flag).
    3. **Which annotators need re-running** — per-predictor staleness decision (new predictor → run only it; version/parameter change, e.g. SpliceAI `-D 10000`→`4999` or the `PLT-139` Pangolin db fix → re-run only that predictor and invalidate its old columns). Must never leave stale columns from an old version silently alongside fresh ones.
    4. **Input format for the re-run** — feed the previous annotated output back in as input. Options to evaluate: (a) keep the annotated VCF and add only the new INFO/CSQ fields (VCF-native, lossless for what's already in it, but tools like VEP re-emit/append to existing CSQ and need care to avoid duplicate/clobbered fields); (b) convert the parsed `.pq`/TSV back to VCF (`universal_variant_converter.py` goes the other direction in practice — check whether a lossless round trip exists; the parsed table is likely lossy for multiallelics/raw INFO); (c) use the old output only as a lookup keyed on CHROM/POS/REF/ALT and join the new annotators' results onto it. Prefer whichever preserves the native VCF as authoritative input (global rule: native formats are authoritative; parsed tables are derived).
    5. **Provenance of the merged result** — the new manifest must record, per annotation column, which run/version produced it (mixed-lineage output), and link back to the parent run.
  - **Depends on**: the run provenance manifest, already available for `annotate_vcf.nf` (the `main.sh` manifest is no longer planned: bash path deprecated 2026-10-02). Variant identity must be normalized (left-aligned, split multiallelics) the same way in both runs or the join silently drops/duplicates records.
  - Not scoped: implementation, which entry point goes first (settled 2026-10-02: `annotate_vcf.nf`, `main.sh` is deprecated).

## 🧬 Phase 5: Future Predictor Integrations
- [ ] **SAI-10k-calc Integration (SpliceAI-10k calculator, Canson et al. 2023, Bioinformatics btad179)**
  - Deterministic post-processor over raw SpliceAI delta scores: predicts splicing aberration type (pseudoexonization, partial/whole intron retention, partial exon deletion, (multi)exon skipping), aberration size (bp), reading-frame effect, and predicted amino acid sequence.
  - Belongs in the annotation pipeline (per-variant, deterministic, computed once — same shape as SPiP/Pangolin/Branchpointer), not in `clinical_variant_prioritization`; the app would just read the resulting columns.
  - **Inputs already available**: `SpliceAI_pred_DS_AG/AL/DG/DL` + `DP_AG/AL/DG/DL` from `src/python/annotate_spliceai.py`; RefSeq NM_ transcript IDs already in `resources/gene_transcript_mapping.txt`.
  - **Open items before implementation**:
    - Window mismatch: confirmed (see **Priority 0** at the top of this file) — SAI-10k-calc's thresholds were calibrated on `-D 4999` output, and `-D` changes the reported delta *score*, not just its position, so this needs the pipeline's `-D 4999` fix landed first, then its own dedicated pass.
    - SNV-only tool; this pipeline also annotates indels — new columns need an explicit `not_applicable` status-contract value for indels (not blank/0, to avoid the PRED-6-style "not scored" vs "confidently benign" conflation).
    - Wrap the published R implementation (https://github.com/adavi4/SAI-10k-calc) as a subprocess rather than reimplementing — the real decision logic is in a supplementary flowchart (Supplementary File S1) not available locally; porting it from the paper's summary text would mean guessing at the algorithm.

Prioritization criterion (user, 2026-09-24): **priority = the tool's output is direct evidence for finding a pathogenic variant in Mendelian (cardiac) disease**; everything else is pending. Any new score enters informational-only (status contract `scored`/`not_covered`/`not_applicable`, no effect on `NEW_IMPACT`/`PRIORITY_TIER`) until a threshold is calibrated on cardiac data — same policy as MaxEntScan (`PRED-11`).

#### Priority

- [ ] **NCBoost v2** — trained specifically on Mendelian pathogenic non-coding SNVs (promoters, UTRs, deep intronic).
  - Before integrating: confirm a GRCh38 genome-wide precomputed release and its license; if it exists, a VEP `--custom` lookup is enough (broad-safe tier).
  - Caveat: training set includes HGMD/ClinVar pathogenic variants — any evaluation on ClinVar-derived truth is circular.
- [ ] **ReMM** — Mendelian non-coding pathogenicity score, the engine behind Genomiser. Precomputed GRCh38 SNV scores exist (Exomiser data release) → VEP `--custom`, broad-safe.
  - **Must not be used with a default threshold**: the review doc's own HKGP evidence shows default ReMM floods the candidate list and *lowered* diagnostic sensitivity vs. Exomiser. Threshold must be calibrated (take the HKGP value from the source paper, not from the doc — the number is lost in the docx export) before it touches ranking.
- [ ] **SQUIRLS** — interpretable splice-variant classifier trained on Mendelian pathogenic non-canonical splice variants; complements SpliceAI outside the canonical ±1/2 dinucleotides (exactly where ClinGen SVI PP3/BP4 applies). Standalone Java on VCF; tier (broad vs. gene-restricted) to be decided from real cost, per `ORCH-10` policy.
- [ ] **AbSplice (GTEx `Heart - Left Ventricle` / `Heart - Atrial Appendage`)** — the only tool on the list that provides *real* cardiac subtissue-specific splicing evidence. Still true after 2026-09-25's Pangolin tissue-of-origin patch (see above) — Pangolin's model only has one generic "Heart" channel, not GTEx's LV/AA split.
  - Decide v1 vs. AbSplice2: AbSplice2's added value is developmental splicing, reported mainly for brain/neurodevelopment — verify it adds anything for adult cardiac disease before paying for it.
  - Check for a GRCh38 precomputed release first; live inference needs SpliceAI + MMSplice inputs (MMSplice then comes in as a dependency, not as its own item).
